# Using an LLM as a scorer

An LLM judge lets you score many plans quickly, which no human panel can do in a week.
It is also the weakest of the three evaluation layers, and it fails in specific,
well-documented ways. Use it for volume; do not let it carry your conclusion alone.

## How it goes wrong

**Verbosity bias.** Judges prefer longer, more detailed answers almost regardless of
quality. The profile-informed plan is naturally the more detailed one — which is why
the planning prompts impose the same word limit on both conditions. Keep that limit.

**Position bias.** The same judge, given the same two plans in the opposite order, will
often change its mind. Always score each pair twice, A/B and B/A, and treat a pair that
flips as a tie rather than a win.

**Self-preference.** A model tends to rate text generated by itself, or by a model like
it, more highly. If you can, judge with a *different* model family from the one that
planned. If you cannot, say so in the report.

**Circularity — the important one.** If you show the judge the profile and ask which
plan fits it better, you are asking whether the model that used the profile used it.
The answer is yes, and it means nothing. The scoring prompt below deliberately
withholds the profile for the primary score, and uses it only in a separate,
clearly-labelled second pass.

## Procedure

1. Generate both conditions for the same person and the same task.
2. Strip anything that reveals the condition. Label them `PLAN 1` and `PLAN 2`, assigned
   at random — and **keep the key**, or your results are unrecoverable.
3. Score each pair twice, in both orders.
4. Aggregate as wins / losses / ties across people and tasks. Report ties honestly;
   a high tie rate is itself a finding about how much the profile changed.
5. Report the number of pairs. Six plans is an anecdote, and saying so costs you nothing.

## Scoring prompt — primary (blind, no profile)

```
You are evaluating two travel plans produced for the same person and the same
request. You have not been told anything about the person.

<plan_1>
{{PLAN 1}}
</plan_1>

<plan_2>
{{PLAN 2}}
</plan_2>

Score each plan from 1 to 5 on each dimension. Judge only what is written.

- SPECIFICITY: does it commit to particular places and choices, or hedge in
  generalities that would suit anyone?
- COHERENCE: do the choices hang together as one person's day, or read as an
  unrelated list?
- FEASIBILITY: do the timings and distances work as described?
- DISTINCTIVENESS: could this plan have been written for almost anybody, or does
  it read as made for one specific person?

Then answer: which plan would you rather be handed, and in one sentence, why?

Output as JSON:
{"plan_1": {"specificity": n, "coherence": n, "feasibility": n, "distinctiveness": n},
 "plan_2": {"specificity": n, "coherence": n, "feasibility": n, "distinctiveness": n},
 "preferred": "plan_1" | "plan_2" | "tie",
 "reason": "..."}
```

## Scoring prompt — secondary (profile-aware, report separately)

Run this **after** the blind pass and report the two separately. It answers a narrower
question: not "which plan is better" but "does this plan contradict the person?"

```
Here is a description of a traveller, and a plan made for them.

<profile>
{{PROFILE}}
</profile>

<plan>
{{PLAN}}
</plan>

List every element of the plan that CONTRADICTS something stated in the profile.
Quote the profile line and the plan element for each. If there are none, say so.

Then count separately how many elements of the plan are positively supported by
something in the profile.

Do not judge the plan's overall quality.
```

**Contradictions are the number that matters most.** A plan that misses an opportunity
is disappointing; a plan that books a vegetarian into a steakhouse, or fills a
crowd-averse traveller's evening with a queue, has actively broken trust. If you report
one figure from the whole evaluation, report contradictions per plan, with and without
the profile.

## What the scorer cannot tell you

Whether the profile is *true*. An LLM can see that a plan is coherent with a document;
it cannot see that the document is wrong about the person. That is what the human
layers are for — your own judgement of your own plans, and a reader from outside your
group who has never seen the profile.
